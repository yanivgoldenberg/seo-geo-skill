# Recurring SEO review adapter

For recurring health/search reviews, changed source facts or competitor sitemap observations, use [the pinned operating reference](https://github.com/yanivgoldenberg/YG-WEBSITE-CONTENT-FLOW/blob/9b577f497f37a7ee1b793f8c8211c7778baaab45/docs/SEO_OPERATIONS.md). Its exact source revision and reference hash are recorded in [seo-operations-pin.json](seo-operations-pin.json).

Keep one existing action queue with source/date/coverage, existing page and locale, evidence confidence, priority rationale, allowed effects, next action and outcome review. Read the actual source diff before identifying stale claims; implemented behavior, approved offer facts and public availability have different authorities. Follow affected copy through visible pages, locale counterparts, FAQs/schema and derived surfaces. Send supported corrections through the current semantic and native release gates.

For selected competitors, retain complete bounded sitemap snapshots before comparing URL sets. A first snapshot is a baseline; failed or capped coverage stays UNKNOWN. Sitemap additions/removals and `lastmod` changes are observations, not publication, indexing, demand or ranking proof. Read selected pages and reconcile same-intent coverage before recommending a change.

Use existing GSC, buyer-research and expert-handoff records. Maintain existing mutation limits and native acceptance; this adapter grants no additional effects. It activates no scheduler, provider account, paid service, outreach or deployment and promises no ranking timeline. Apply [semantic acceptance](../SEMANTIC_ACCEPTANCE.md) to substantive page work.
